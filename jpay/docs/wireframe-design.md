# PairPay 와이어프레임 & UI/UX 설계서

## 1. 화면 구조 개요

### 화면 계층 구조
```
App (Root)
├── OnboardingFlow
│   ├── Welcome
│   ├── CodeInput/Create
│   └── ProfileSetup
├── MainApp
│   ├── Dashboard (메인)
│   ├── AddExpense
│   ├── BudgetManagement
│   ├── ExpenseList

    └── Modals
```

## 2. 주요 화면별 와이어프레임

### 2.1 대시보드 (Dashboard)
**화면 목적**: 공동 지출 현황을 한눈에 파악할 수 있는 메인 허브

```
[Header]
  PairPay 로고 | 페어명 | 설정 아이콘

[Balance Card]
  현재 잔액 상태
  - "A가 B에게 ₩15,000 받을 금액"
  - 큰 숫자로 강조 표시

[Quick Stats Grid - 2x2]
  ┌─────────────┬─────────────┐
  │ 이번 달     │ 어제 지출   │
  │ 총 지출     │ 금액        │
  │ ₩450,000   │ ₩35,000    │
  └─────────────┴─────────────┘
  ┌─────────────┬─────────────┐
  │ 예산 대비   │ 가장 많은   │
  │ 사용률      │ 카테고리    │
  │ 75%        │ 외식        │
  └─────────────┴─────────────┘

[Budget Progress Bar]
  월 예산: ₩600,000 / ₩800,000
  [████████░░] 75%

[Recent Expenses (최근 3개)]
  • 스타벅스 커피     ₩8,500  (A 결제)
  • 마트 장보기      ₩45,000 (B 결제)  
  • 영화 티켓       ₩32,000 (A 결제)

[FAB: + 지출 기록]
```

### 2.2 지출 기록 (Add Expense)
**화면 목적**: 4번 클릭 이내로 빠른 지출 입력

```
[Header]
  ← 뒤로 | 지출 기록 | ✓ 저장

[Form Fields]
  금액 입력*
  [₩ ___________] (큰 입력 필드)
  
  카테고리 선택*
  [외식] [교통] [쇼핑] [생활] [기타]
  
  결제자*
  ○ A (나)  ○ B (상대방)
  
  분담 방식
  ○ 반반 (기본값)  ○ 전액 A  ○ 전액 B  ○ 직접 입력
  
  메모 (선택)
  [간단한 설명...]
  
  날짜
  [2024-01-15] (기본값: 오늘)

[하단 버튼]
  [저장하기] (primary)
```

### 2.3 예산 관리 (Budget Management)
**화면 목적**: 월별/카테고리별 예산 설정 및 추적

```
[Header]
  ← 뒤로 | 예산 관리 | 편집

[Current Month: 2024년 1월]

[Total Budget Card]
  월 총 예산: ₩800,000
  사용 금액: ₩600,000 (75%)
  [████████░░] 
  
[Category Budget List]
  외식      ₩200,000 / ₩250,000  [████████░] 80%
  교통      ₩80,000  / ₩100,000  [████████░░] 80%
  생활용품  ₩150,000 / ₩200,000  [██████░░░░] 75%
  쇼핑      ₩170,000 / ₩250,000  [██████░░░░] 68%

[Progress Indicators]
  🔴 80% 초과 (주의)
  🟡 60-80% (보통)  
  🟢 60% 미만 (양호)

[하단 버튼]
  [예산 수정하기]
```

### 2.4 내역 리스트 (Expense List)
**화면 목적**: 상세한 지출 내역 조회 및 필터링

```
[Header]
  ← 뒤로 | 지출 내역 | 필터

[Month Navigation]
  ← 2023.12 | 2024.01 | 2024.02 →

[Summary Card]
  1월 총 지출: ₩600,000
  A: ₩320,000 (53%) | B: ₩280,000 (47%)

[Filter Chips]
  [전체] [외식] [교통] [생활] [A 결제] [B 결제]

[Expense List]
  2024.01.15
  • 스타벅스 커피     ₩8,500   A 결제  [외식]
  • 마트 장보기      ₩45,000  B 결제  [생활]
  
  2024.01.14  
  • 지하철 요금      ₩2,800   A 결제  [교통]
  • 점심 식사       ₩28,000  B 결제  [외식]
  
  (무한 스크롤로 더 많은 내역...)
```

### 2.5 정산 (Settlement)
**화면 목적**: 명확한 정산 금액 계산 및 처리

```
[Header]
  ← 뒤로 | 정산하기 | 

[Settlement Card]
  ┌─────────────────────────┐
  │  A가 B에게 보낼 금액    │
  │                         │
  │      ₩15,000           │
  │                         │
  │  A 총 지출: ₩285,000   │
  │  B 총 지출: ₩315,000   │
  │  차액: ₩30,000 ÷ 2     │
  └─────────────────────────┘

[Payment Methods]
  💳 카카오페이로 보내기
  🏦 계좌이체로 보내기
  💰 현금으로 정산하기

[하단 버튼]
  [정산 완료] (정산 후 잔액 0으로 리셋)
```

## 3. 네비게이션 구조

### 하단 탭 네비게이션
```
[홈] [예산] [내역] [설정]
 🏠   📊   📋   ⚙️
```

### Floating Action Button (FAB)
- 모든 화면에서 접근 가능한 "+ 지출 기록" 버튼
- 메인 액션이므로 눈에 띄는 색상과 위치

## 4. 반응형 설계 고려사항

### 모바일 우선 (Mobile First)
- 최소 너비: 320px
- 터치 타겟: 최소 44px
- 한 손 조작 가능한 UI 배치

### 터치 최적화
- 스와이프 제스처 지원 (월 전환, 삭제 등)
- 길게 누르기로 빠른 편집
- 풀 투 리프레쉬

## 5. 접근성 고려사항

- 색상만으로 정보 전달하지 않기
- 충분한 대비율 확보
- 스크린 리더 지원
- 키보드 네비게이션 지원
